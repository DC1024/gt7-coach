02怎么做到的

三条设计原则，后面所有取舍都服从它们。

01

判断在本地，措辞才上云

「该不该说、说的是哪个数」全部由本地确定性代码完成 —— 毫秒级、零成本、不会编数字。 只有「把结论变成一句人话」这一层留给云。而且必须是可选的：断网的车库里也要能全功能工作。

反过来做（让大模型看着遥测自己判断）必翻车：一次调用 0.5~2 秒，而 250 km/h 时 2 秒等于 139 米 ——「T1 刹车点提前 10 米」晚 139 米就是废话，而且模型会编数字。

02

按延迟分档，硬实时档禁走云

档延迟预算生成方式触发场景
A 硬实时< 300 ms本地规则刹车点 / 弯心 / 给油 / 打滑 / 出界
B 圈后< 2.5 s本地算 + 云润色每圈结束的 delta 与归因
C 问答< 3 s云模型用户主动提问
03

不打扰，优先于多说话

一个话痨副驾比没有副驾更糟。所以有四道闸拦着：同类冷却 20 秒、跨类冷却 6 秒、 每圈上限 6 句、同一个弯只提醒一次。

再加一条弯中禁言：横向加速度超过 0.8 G 时只念 4 字以内的短句， 没有短句就干脆不说 —— 那时玩家手上没空听句子。

03教练和仪表盘，不是一回事

仪表盘告诉你现在；教练告诉你你的习惯。这是它俩最大的分工。

仪表盘：当前状态

四轮胎温、油量续航、实时 delta、下一刹车点距离 —— 你看一眼就知道的信息。

教练：跨圈累积

同一个弯连续 3 圈中位亏 0.3 秒以上才开口，之后隔 3 圈再说一次。它记着你的模式。

05数据边界（诚实清单）

GT7 遥测是单车流，有些东西就是拿不到。不许编是硬规矩。

只有你一台车的数据
✗ 不能说「Hamilton 在你后面 0.8 秒」，只能说名次
胎压 / 胎耗（格式 A 恒为 0）
✗ 不能说「胎耗 12%」，只能说胎温
协议没有转向角
✓ 已用曲率 κ = G_lat·g/v² 替代（半径 + 左右方向）
没有赛道里程碑
✗ 不能说「100 米标刹车」，只能说「1.5 秒后重刹区」

最后一条恰好是这个项目的性格：说不了精确的距离，就说你来得及反应的时间。 「1.5 秒后重刹区」比「100 米标刹车」在 250 km/h 和 80 km/h 下都成立。

06开始使用

需要 Python 3.10+。不需要 pip install 任何东西 —— 整个包只用标准库。 

# 1. 自检：用内置的合成赛道跑一遍，不连任何东西
python -m gt7coach demo
# 打开 http://127.0.0.1:8788/ 按一下就能听

# 2. 接真车（配合 GT7 Dash 使用）
python -m gt7coach serve --dash http://192.168.43.18:8787

# 3. 排障：跑几次 tick，把状态打到 stdout
python -m gt7coach once --dash http://192.168.43.18:8787

# 4. 离线调参：改阈值不用上车
python -m gt7coach replay 场次.jsonl --conf brake_late_m=12
# 拿历史场次跑一遍，直接打出「会说的话」列表 + 逐圈统计

或者用 Docker，一条命令：

git clone https://github.com/DC1024/gt7-coach && cd gt7-coach
docker compose up -d
curl http://127.0.0.1:8788/api/v1/coach/health

要配合 GT7 Dash

遥测接收 + 仪表盘由 gt7-dash 负责。两个仓库只通过 HTTP 契约耦合，各跑各的进程，可以跨机器。

启动顺序无所谓

教练连不上 Dash 时会退避重试（2s → 15s），Dash 起来后自动接上，不会崩。

完全离线可用

云端只留给可选的「措辞润色」。不配任何 key，功能一个不少 —— 只是措辞走本地模板。
