# GT7 赛道工程师（Race Engineer）

给 PS5《GT7》当**实时副驾**：盯着遥测数据，在你该被提醒的时候说一句话。

不是事后剪辑解说，是**边开边说**。配合 [GT7 Dash](https://github.com/DC1024/gt7-dash)
（遥测接收 + 仪表盘）一起用；也能对着任何实现了 GT7 Dash 公开 v1 接口的服务跑。

> **状态：R1 + R1.5 已上线 —— 纯本地闭环，零云依赖，一行云调用都没有。**
> 所有判断在本地确定性代码里完成。云端只保留给后续的「措辞润色」与「问答」，
> 而且必须是**可选**的：这个服务在断网的车库里也要能全功能工作。

## 快速开始

```bash
# 1. 自检：用内置的合成赛道跑一遍，不连任何东西
python -m gt7coach demo
open http://127.0.0.1:8788/          # 自带验证页，按一下就能开语音

# 2. 接真车
python -m gt7coach serve --dash http://192.168.43.18:8787

# 3. 排障：跑几次 tick，把状态打到 stdout
python -m gt7coach once --dash http://192.168.43.18:8787
```

纯标准库，Python 3.10+，不需要 `pip install` 任何东西。

## 与 GT7 Dash 的接口

两个仓库**只通过 HTTP 契约耦合**，各跑各的进程，可以跨机器。

### 一、走出去（Coach → Dash）：只读公开 v1 接口

| 用途 | 接口 | 频率 |
|---|---|---|
| 当前帧 | `GET /api/v1/live` | 10 Hz |
| 找正在录制的场次 | `GET /api/v1/sessions`（看 `live` 字段） | 无参考圈时 2 s / 有之后 15 s |
| **参考圈剖面** | `GET /api/v1/sessions/<f>/profile` | **仅在参考圈需要换时**（换场 / 最快圈刷新） |

关于 `/profile`，两点必须说清楚：

- 它是 GT7 Dash 侧**已有分析能力的打包出口**（`clean_laps` / `lap_samples` /
  `find_peaks_valleys` / 距离重采样），一次返回「几何折线 + 等距遥测 +
  刹车入点/弯心/给油点」。消费方自己重写一遍不仅费力，还会因为实时侧只有
  10 Hz 轮询而精度更差、第一圈完全没有参考。
- 它的距离轴是**几何弧长**（相邻坐标弦长累积），不是速度积分。速度积分
  一圈漂移 60~300 m，拿它做「本圈 1200 m vs 参考圈 1200 m」对齐会差十几米，
  刹车点预告直接指错位置。

**这个端点是可选的。** 拿不到时 Coach 自动退回「自己拿实时帧攒参考圈」，
代价是第 2 圈起才有参考、精度 10 Hz。`CoachState.stats.ref_source` 会如实
写 `"profile"` 还是 `"self"`，`warnings` 里也会说明 —— 不允许静默降级。

### 二、走进来（Dash → Coach）：教练自己的 HTTP 接口

默认监听 `8788`（紧挨 Dashboard 的 `8787`，不抢）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/coach/state` | **电平**：完整状态，每次都返回当前该说的 |
| GET | `/api/v1/coach/say` | **边沿**：只给还没播报过的，取走即清空 |
| GET | `/api/v1/coach/history` | 最近播报（`?n=20`） |
| GET | `/api/v1/coach/config` | 当前阈值配置 |
| POST | `/api/v1/coach/config` | 改阈值，`{"gate": {"max_per_lap": 3}}` |
| GET | `/api/v1/coach/health` | 存活 / tick 数 / 参考圈状态 |
| GET | `/` | 自带验证页（不依赖仪表盘就能听） |

全部带 `Access-Control-Allow-Origin: *`（仪表盘是另一个源，没有 CORS 头
浏览器会直接拦掉）。

**为什么两种语义都要有**：电平适合轮询式前端（不关心漏没漏，看当前状态就行）；
边沿适合播报场景（播完就得忘掉，不用前端自己写去重）。只给一种，就会逼消费方
写一个和这里重复的逻辑。

`state` 的完整结构见 [`gt7coach/contract.py`](gt7coach/contract.py) ——
那份文件就是契约本身，字段**只加不改**，破坏性改动必须升 `COACH_API_VERSION`。

```jsonc
{
  "api_version": 1,
  "connected": true,
  "ref_ready": true,          // 参考圈是否就绪
  "ref_lap": 3, "ref_len_m": 3769.6,
  "lap": 4,
  "s_m": 1240.5,              // 本圈已跑距离（沿参考圈的弧长）
  "delta_s": -0.213,          // 相对参考圈的时间差，负 = 更快
  "ref_speed_kph": 178.2,
  "next_brake_m": 96.4, "next_brake_s": 1.7,
  "say": [                    // 这一 tick 决定要说的话（通常 0 或 1 条）
    {"key": "brake_warn@1300", "text": "1.7 秒后重刹区，参考最低 92",
     "short": "准备刹车", "priority": 1, "evidence": {"t_go_s": 1.68}}
  ],
  "spoken": [ /* 最近播报历史 */ ],
  "stats": {"ref_source": "profile", "lateral_m": 1.2,
            "wheel_radius_m": {"front": 0.3391, "rear": 0.3435}}
}
```

### 三、语音

**默认让浏览器念**（`speechSynthesis`，Web Speech API）：零成本、零依赖、
零网络，首字延迟 ~0.1 s。音色偏机械 —— 但赛道工程师本来就该是短促无线电味。

Coach 自己不出声，只给文本；**出声是消费方的事**。README 顶部的
`http://127.0.0.1:8788/` 验证页里有最小实现可以直接抄。

## 三条设计原则

后面所有取舍都服从这三条。

### 1. 判断在本地，措辞在云上

| 环节 | 谁做 | 为什么 |
|---|---|---|
| 该不该说、说的是哪个数 | **本地代码** | 毫秒级、零成本、不会编数字 |
| 把结论变成一句人话 | 云 LLM（可选） | 只有这里有增量价值 |

反过来（让 LLM 看着遥测自己判断）必翻车：一次调用 0.5~2 s，250 km/h 时
2 秒 = **139 米** ——「T1 刹车点提前 10 米」晚 139 米就是废话；而且 LLM 会编数字。

### 2. 按延迟分档，硬实时档禁止走云

| 档 | 延迟预算 | 生成 | 触发 |
|---|---|---|---|
| A 硬实时 | < 300 ms | 本地规则 | 刹车点 / 弯心 / 给油 / 打滑 / 出界 / 换挡 / 胎温 |
| B 圈后 | < 2.5 s | 本地算 + 云润色 | 每圈结束的 delta 与归因 |
| C 问答 | < 3 s | 云 LLM | 用户主动提问 |

R1 把 A 档和 B 档的本地部分都做完了。

### 3. 不打扰优先于多说话

一个话痨副驾比没有副驾更糟。四道闸：

1. **同类冷却** 20 s、**跨类冷却** 6 s（更紧急的话可缩短到 2 s 插队）
2. **弯中禁言**：`|G| > 0.8` 时只念 `short`（≤ 4 字），没短句就干脆不说
3. **每圈上限**：非紧急播报 6 句
4. **只报新信息**：同一个 key 每圈只报一次；key 里带位置标识
   （`brake_late@400`），于是天然是「同一个弯只提醒一次」

## 会说什么（R1 全部实现）

| key | 档 | 触发条件 |
|---|---|---|
| `off_track` | P0 | 距参考线横向 > 18 m 持续 0.4 s |
| `slip_front/rear/all` | P0 | 滑移率 > 0.15 持续 0.25 s（半径在线自标定） |
| `brake_late@<刹车区>` | P0 | 已过刹车入点 > 8 m 还没踩刹车（只算到弯心为止） |
| `brake_warn@<刹车区>` | P1 | 距下一个刹车入点 < 1.5 s（比参考快时额外提示） |
| `shift` | P1 | rpm ≥ 换挡灯上限持续 0.5 s |
| `apex_slow@<弯心>` | P2 | 弯中速度比参考低 > 5 km/h |
| `throttle_late@<弯心>` | P2 | 过弯心 40~120 m 油门仍 < 0.3 持续 0.5 s |
| `tyre_hot` / `tyre_cold` | P2 | 任一胎温 > 110 / < 60 °C 持续 2 s |
| `delta` | P3 | 本圈 delta 首次跨过 ±0.2 s |
| `projected_lap` | P3 | 跑过本圈 35% 后预测最终圈速（`参考圈速 + 当前 delta`）|
| `lap_summary` | P3 | 每圈结束报上一圈成绩与参考差 |
| `sector_loss` | P2 | 圈后：指出相对「本场各段最好值」最慢的那一段，并给潜在空间 |
| `fuel_range` | P2 | 圈后：按本场油耗中位数算还能跑几圈（≤3 圈才提醒）|
| `corner_habit@<弯>` | P2 | **跨圈累积**：同一个弯连续 3 圈中位亏 ≥0.3s 才提醒，之后隔 3 圈再说 —— 这是教练区别于仪表盘的地方：仪表盘告诉你**现在**，教练告诉你**你的习惯** |

### 本地能算到什么程度（R1.5）

「不上云」不是把功能砍掉，而是把能本地算的都算完。下面这些**一个接口都不用调**：

| 能力 | 怎么来的 | 为什么不用服务端 |
|---|---|---|
| 分段用时（S1/S2/S3）| 从实时帧的几何弧长按**绝对距离**等分，边界插值 | Dash 的 `/sectors` 每次要重解析整场 jsonl（直播文件一直在变，一场 20 万帧要 2s+ 且越来越贵）|
| 理论最快圈 / 潜在空间 | 本场各段最好值之和 vs 实际最快圈 | 同上 |
| 每圈油耗 / 还能跑几圈 | 圈首圈尾剩余量做差，取近 5 圈**中位数** | 单圈油耗会被慢车/暖胎圈带偏，中位数才稳到能据以决策 |
| 预测圈速 | 参考圈圈速 + 当前 delta | 无线电里最常被问的一句 |
| 轮胎半径自标定 | 自由滚动帧上累计 `Σ(v·ω)/Σ(ω²)`，**前后轴分开** | 实测前 0.3391 / 后 0.3435，合成一个会变成固定偏置 |
| 跨场次历史最快圈 | 场次列表里已有的 `best_lap_s` + **几何形状比对**确认同赛道 | 不用赛道识别（实测 10 场只有 2 场已识别）|

本地分段与 Dash 服务端 `/sectors` 的交叉验证：同一圈 3 段分别
`[33.36, 36.00, 31.63]` vs `[33.379, 35.935, 31.677]`，**每段差 ≤0.07s**。

### 为什么没有"提问通道"（R4，已评估后砍掉）

把 12 个候选问题逐个核对「教练有没有主动说 / 直播页有没有显示 / 详情页有没有显示」之后，
**9 个已经有现成实现**（教练每圈说的成绩与最慢段、直播页的四轮胎温/油量续航/实时 delta/
下一刹车点、详情页的分段计时 · 理论最快圈），真缺口只剩 1 个——
而它已经被 **R1.6 每弯累积失误** 以正确的方式（主动播报）解决了。

推导过程见 `../2026-10-07-02-04-04/R4预设问题与必要性分析_2026-10-09.md`（若在同级工作区）。

### 离线调参（不用上车）

```bash
python -m gt7coach replay 场次.jsonl
python -m gt7coach replay 场次.jsonl --conf brake_late_m=12 --conf gate.max_per_lap=8
python -m gt7coach replay 场次.jsonl --json > a.json   # 调完再跑一次 diff 就知道改了什么
```

拿历史场次跑一遍，直接打出「会说的话」列表 + 逐圈统计 + 闸门丢了多少候选。
阈值以前只能上车试，而"感觉不太对"既慢又没法对比；现在改一个数跑一遍即可。

它第一次跑真实场次就抓出两个**实时侧永远看不到**的 bug：
`lap_buffer` 按帧数裁剪（实时 10Hz 够 300s，但 jsonl 60Hz 只有 50s，装不下一圈），
以及拿菜单帧（`lap=0`）自攒出 390m 的假参考圈把后面全带歪。

### 数据边界（诚实清单）

GT7 遥测是**单车流**，有些东西就是拿不到，不许编：

| 缺口 | 后果 |
|---|---|
| 只有你一台车的数据 | ❌ 不能说「Hamilton 在你后面 0.8 秒」。只能说名次 |
| 胎压 / 胎耗（格式 A 恒为 0） | ❌ 不能说「胎耗 12%」。只能说胎温 |
| 协议没有转向角 | ✅ 已用曲率 `κ = G_lat·g/v²` 替代（半径 + 左右） |
| 没有赛道里程碑 | ❌ 不能说「100 米标刹车」，只能说「1.5 秒后重刹区」 |

## 开发

```bash
python -m pytest tests/ -q      # 106 项，纯标准库
```

测试用**合成赛道**（`gt7coach/synth.py`）而不是真数据 —— 合成圆上每个量都能
手算：圈长 = 2πR、横向 G = v²/(R·g)、刹车区起点就是减速段起点，断言于是能
写成等式，而不是「看起来对」。

几条踩过的坑，都写进了对应位置的注释与测试：

- 闭环折线在起跑线上是同一个点，而游戏的圈计时器与位置**不同步**：
  过线那一帧位置已进新圈（`s≈0`）但圈计时还是上圈的 69.70 s，
  两边相减就是「丢了一整圈」的假 delta（实测 +69.700 s → 修正后最大 0.116 s）
- `brake_late` 必须限制到弯心为止，否则会在出弯直道上报「刹车晚了 155 米」
- 合成帧里 `t` 必须**跨圈单调**（只有 `lap_time_s` 每圈归零），
  与记录器一致；否则回放时冷却永不生效
- 夹具改了速度就必须同步改轮速（`ω = v/R`），不然会造出「四轮抱死」的假象

## 部署（Docker）

```bash
git clone https://github.com/DC1024/gt7-coach && cd gt7-coach
docker compose up -d
curl http://127.0.0.1:8788/api/v1/coach/health
```

镜像基于 `python:3.12-slim`，**不装任何依赖**（整个包只用标准库）。

`network_mode: host` 是刻意的：要连宿主机的 `127.0.0.1:8787`（GT7 Dash）。
bridge 模式下这个地址指向容器自己。

**跑在哪台机器上都行**，因为出声的是浏览器：

| 部署位置 | 浏览器怎么连 | 说明 |
|---|---|---|
| 服务器（和 Dash 同一台） | `http://<服务器IP>:8788` | 最简单，仪表盘卡片默认地址就对了 |
| 玩家电脑（扬声器旁边） | `http://localhost:8788` | 少一跳网络 |

「玩家电脑」方案并不能让声音更早出来 —— TTS 是**浏览器**做的，
音频本来就是从打开仪表盘的那台机器出来的。放服务器上纯粹是为了少一个进程要管。

### 和 GT7 Dash 的启动顺序

无所谓。教练连不上 Dash 时会退避重试（2s → 15s），Dash 起来后自动接上；
反之 Dash 的卡片在教练没起时只显示「未启动」，不影响仪表盘本身。

### 部署脚本（`tools/`）

```bash
export GT7_SERVER_PASSWORD=...        # 凭据只从环境变量读，绝不进仓库
python tools/deploy.py --host 192.168.43.18 --dash-dir ../2026-10-07-02-04-04
python tools/verify.py  --dash http://192.168.43.18:8787 \
                        --coach http://192.168.43.18:8788
```

`deploy.py` 的顺序是 **备份 → 上传 → md5 硬校验 → 重建镜像 → 重启 → 再验容器内 md5**。
md5 那两步不能省：镜像里的代码靠 Dockerfile 的 `COPY` 烤进去，
"文件传到服务器了" ≠ "镜像里是这份" —— 漏了重建镜像时现象只是"新功能没生效"。

`verify.py` 走真实网络查五件事，其中**单列了 tick 速率**：
慢的依赖绝不能阻塞 tick（详见下面「已知代价」）。

### 已知代价

GT7 Dash 的 `GET /api/v1/sessions` **冷态约 11 秒**（要流式扫每个场次文件才能
给出列表里的「最快圈」，实测 5 场里有个 111 MB 的），而容器每次重启都会回到冷态。
热态是 0.01 秒。

Coach 曾经把这一句同步写在 tick 里 → 10Hz 掉到 0.3Hz、`/health` 看起来像
"服务挂了"（实际两边都正常）。**现已改为后台线程 + 独立状态**：
tick 永远不等待，`sess_state` 单独暴露（`loading` / `ok` / `empty` / `failed`），
慢接口用 40 秒超时（它不在 tick 路径上，等得起）。
实测：仪表盘冷态下 tick 仍是 10.0/s。

副作用是仪表盘重启后，教练最多要 ~11 秒才能认出「哪一场在直播」。
想让这段也消失，得把 Dash 侧的最快圈缓存落到磁盘 —— 那是 Dash 的改动，尚未做。
